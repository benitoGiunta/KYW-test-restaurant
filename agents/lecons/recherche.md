# Leçons recherche-client
Nouvelle leçon : une ligne datée à la fin de ce fichier.
- Quota WebSearch épuisé : relancer un WebSearch de test avant de conclure (il revient entre deux passes) ; lancer les recherche-client en début de tour ; repli : BCE `kbopub.economie.fgov.be/kbopub/zoeknummerform.html?nummer=<BCE>&actionLu=Rechercher&lang=fr`, Nominatim pour la géolocalisation, Rankeat (note Google, horaires), Le Fooding (prix), Mapstr (extraits d'avis).
- WebFetch renvoie une page vide sur guide.michelin.com (rendre avec `capture-site.mjs`) ; Tripadvisor et Facebook donnent 403 : extraits d'avis en paraphrase via WebSearch seulement ; une fiche tierce (Gault&Millau) qui contredit la fiche officielle : « à confirmer ».
- Les sites E-net Business : le bloc « avis de nos clients x/5 » est un module de l'agence, jamais un avis sur le restaurant ; le texte des pages internes contient des coquilles à ne pas recopier ; les sliders contiennent des doublons de photos (dédupliquer par hash perceptuel PIL 16×16 puis planche-contact avant de nommer) ; les onglets de carte portent des ancres `#onglet_<slug>-<id>` et leurs prix complets ne sont que dans `page.html`.
- Une carte en images (WordPress/Divi, GIF) : extraire les `<img>` de `page.html` et lire les GIF convertis en PNG par PIL ; une carte en texte HTML : strip des balises plutôt que lire les captures.
- Recouper l'adresse de `data/restaurants.json` avec le pied de page du site du client (elle peut être celle d'un autre établissement).
- Les descriptions de technologies et de mécaniques d'un site sont à vérifier dans le HTML (les faux positifs abondent) ; ne rien affirmer sans preuve ; avis Google et abonnés `null` sauf affichage par le site.
- 2026-11-01 : site WordPress/Elementor avec agenda : la page restaurant donne la carte en texte HTML (strip des balises) ; l'adresse de restaurants.json est le siège BCE, le site donne une autre adresse (Rue Lelièvre 4).
- 2026-11-01 : site Next.js sur mesure (carte en texte HTML dans /carte/, strip des balises) ; la note de restaurants.json annonçait une réservation en ligne alors que le site n'accepte que le téléphone ; les posters vidéo (hero-poster.jpg) peuvent montrer autre chose que la vidéo.
- 2026-11-06 : site WordPress (Poush) avec carte en PDF (pdftotext -layout, colonnes mélangées : reclasser les plats à la main) ; TripAdvisor/Facebook inaccessibles, Rankeat donne note Google et GPS.
- 2026-11-07 : site Webflow/Astro avec carte en PDF (pdftotext -layout, deux colonnes lisibles) ; les « polaroïds » du site sont des vignettes de moins de 250 px (inutilisables) ; l'email de restaurants.json est personnel (non repris) et le communiqué Prezly cité est introuvable ; horaires contradictoires entre G&M, Le Fooding et Table de Terroir.
- 2026-11-07 : site WordPress/Enfold (l-essentiel) : photos d'origine 4724 px accessibles en retirant le suffixe `-WxH` de l'URL (réduire à 2400 px) ; la page « /actualites/ » est en fait Recrutement ; carte en texte HTML avec résidus Word (strip des balises) ; détection techno next/react/vue = faux positifs.
- 2026-11-09 : site PHP Colorlib (ferme-blanche-d-asie) : carte dans des onglets `tab-N` de menu.php (parser les `.menu-item`), photos réelles dans photos.php (`img/menu/N.jpg`), les `*_dark.jpg` du slider sont des doublons assombris ; photos filigranées photographe ; menus de fêtes en affiches PNG à transcrire à l'œil ; Trouve Ton Resto et Resto.be se lisent en curl (JSON-LD avec GPS et note).
- 09/11/2026 : n'utilise jamais une photo portant le filigrane ou le logo d'un tiers (plateforme, annuaire, photographe) ; préfère une photo libre marquée comme illustrative (cas de Ferme Blanche d'Asie, photos filigranées « Find Your Place »).
