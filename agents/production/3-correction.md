# Étape 3 — Corriger les 3 sites d'un restaurant

Version : **correction, approche 4** (`VERSIONS.md`). Une session par restaurant, créée par la session mère quand le
développement du restaurant est terminé : `create_session` avec le modèle `claude-haiku-5-5` explicite, dépôt et
branche de `parametres.md`, tag `kyw-<campagne>`. Remplacer `<slug>`, `<vars>` (en général `portfolio awwwards legacy`),
`<extra>` (vide, ou consigne particulière pour une reprise), `<phase>`, `<campagne>`, `<consigne-lecons>`,
`<heure-limite>`, `<session-mere>`, `<session-reporting>`. Ne rien changer d'autre : c'est ce message qui fixe la version.

L'orchestrateur lance les captures par page (`scripts/captures-pages.sh`, qui active aussi le garde-fou du marqueur
pour ces sites), puis un agent `identifier-rectifier-site` (Sonnet, `.claude/agents/identifier-rectifier-site.md`)
par site, contrôle la couverture, relance une fois les revues incomplètes, publie et mesure.
