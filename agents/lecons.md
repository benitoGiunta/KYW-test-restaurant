# Leçons structurelles (auto-amélioration)

Chaque agent qui rencontre un problème de méthode, d'outillage ou un piège répétable l'ajoute ici en fin de tâche :
`- [date] [rôle] [restaurant] : problème → correction appliquée / règle à suivre`. Les agents lisent ce fichier au démarrage.

- 2026-10-28 orchestrateur : `pnpm install` échoue si `package.json` porte `packageManager` (corepack absent) → ne pas le déclarer.
- 2026-10-28 orchestrateur : esbuild et sharp ont besoin de `pnpm.onlyBuiltDependencies` dans le package.json racine, sinon leurs scripts sont ignorés.
- 2026-10-28 orchestrateur : en mode Auto, écrire dans `.claude/settings.json` est refusé (auto-modification) ; ne pas compter sur des règles d'autorisation commitées.
- 2026-10-28 orchestrateur : le HTML brut d'un site tiers capturé contenait un jeton Mapbox et GitHub a refusé le push (push protection) → page.html est gitignoré et capture-site.mjs masque les jetons ; ne jamais `git add -A` sans vérifier ce que les agents de recherche ont déposé.
- 2026-10-28 orchestrateur : le quota WebSearch (200 requêtes) est partagé par TOUS les agents lancés dans un même tour de la session mère ; au-delà, les agents n'ont plus que WebFetch. Conséquence : un restaurant = une session fille (quota propre) ; dans une même session, ne pas lancer plus de 3 agents gourmands en recherche en parallèle, et prévoir le repli WebFetch (galeries, annuaires) dans les prompts.
- 2026-10-28 recherche-client les-potes-au-feu : le quota WebSearch de la session (200 par tour, partagé entre agents) était déjà épuisé au lancement → l'orchestrateur doit lancer les recherche-client en début de tour ou limiter les recherches des autres agents ; en repli, accéder directement aux fiches (BCE `kbopub.economie.fgov.be/kbopub/zoeknummerform.html?nummer=<BCE>&actionLu=Rechercher&lang=fr`, Guide MICHELIN `guide.michelin.com/fr/fr/<province>/<ville>/restaurant/<slug>` rendu avec `capture-site.mjs` car WebFetch renvoie une page vide, Nominatim pour la géolocalisation).
- 2026-10-28 recherche-client les-potes-au-feu : Facebook, Instagram (même le plugin de page), TripAdvisor, TheFork, Google Maps, Restaurant Guru et Gault&Millau (certificat expiré) sont inaccessibles depuis la session (login wall / 403 / 503) → ne pas y consacrer plus d'une tentative chacun ; avis Google et abonnés restent `null` sauf si le site du client les affiche.
- 2026-10-28 recherche-client les-potes-au-feu : sur les sites E-net Business, le bloc « Les avis de nos clients x/5 » est un module de l'agence (avis sur E-net, pas sur le restaurant) → ne jamais le reprendre comme avis clients.
- 2026-10-28 orchestrateur : la limite d'usage de 5 h du compte (partagée par toutes les sessions et agents) a tué 7 agents en parallèle d'un coup (HTTP 429) ; un agent tué se relance par SendMessage après la réinitialisation, une session fille tuée doit recevoir un nouveau message « continue ». Règle : au plus 3 à 4 agents lourds en parallèle, et l'orchestrateur garde une relance planifiée (send_later) pour réveiller ce qui est tombé.
- 2026-10-28 portfolio-evaluation lot 4 : le scratchpad `/tmp/claude-0/.../scratchpad` est partagé entre tous les agents frères d'une même session mère → un agent a écrasé mon `run-captures.sh` et `captures.log` (noms génériques). Préfixer chaque fichier temporaire par le nom du lot (`lot4-…`) et suivre l'avancement via `data/portfolio/captures/<slug>/infos.json`, pas via un journal.
- 2026-10-28 portfolio-evaluation lot 4 : « un seul Chromium à la fois » n'est pas tenable quand plusieurs agents d'évaluation tournent en parallèle (5 captures simultanées observées) ; sur les pages lourdes (Framer 9 Mo, 275 requêtes) Chromium se ferme avant les captures mobile (`Target page… has been closed`). Relancer la capture d'un site isolément si `infos.json` contient `CAPTURE:` et qu'il manque `mobile-haut.png`.
- 2026-10-28 portfolio-evaluation lot 4 : les portes d'âge (Patrón), modales promotionnelles (Odette, Milk Bar `$20 OFF`) et bandeaux cookies restent sur toutes les frames de `capture-site.mjs` → ajouter au script un clic sur les boutons `Accept|Accepter|Aceptar|No thanks|×` et la saisie d'une date de naissance avant les captures ; en attendant, noter `capture_partielle` dans l'éval et juger sur les frames où le contenu est visible.
- 2026-10-28 portfolio-evaluation lot 6 : `capture-site.mjs` capture des pages vides ou bloquées sur trois types de sites : intro vidéo à sauter (diverxo.com : « Saltar video »), modale d'information + cookies (enigmaconcept.es) et preloader jamais levé en headless (masanyc.com : desktop noir, hauteur 900, seul le mobile rend) → prévoir dans le script un clic sur les sélecteurs usuels (`text=Saltar`, `[class*=close]`, `text=Accept`), un `Escape`, un défilement à la molette (Lenis/ScrollSmoother ignorent `scrollTo`) et, en repli, lire `mobile-pleine-page.png` découpé en tranches avec PIL. Les scripts temporaires doivent vivre dans `scripts/` (sinon `playwright` est introuvable depuis le scratchpad) et être supprimés après.
- 2026-10-28 portfolio-evaluation lot 6 : un lot de 14 sites dépasse la limite de 10 min d'une commande en arrière-plan → lancer les captures par paquets de 7 maximum, ou un site à la fois.
- 2026-10-29 portfolio-evaluation lot 3 : `capture-site.mjs` défile avec `scrollTo` + attente de 0,9 s ; sur les sites Lenis/ScrollTrigger (Shorodo) ou à intro bloquante (Giacosa, Sublimotion) les 6 frames sont identiques → faire une seconde passe à la molette (`page.mouse.wheel` par pas de 700 px, attente 10 s pour le préloader, clic sur « Accept all » / « ENTER ») ; les captures `p2-*.png` dans le dossier du site viennent de cette passe. Un script Playwright hors du dépôt échoue (`Cannot find package 'playwright'`) : le copier dans `scripts/` le temps de l'exécution.
- 2026-10-29 portfolio-evaluation lot 3 : bandeaux cookies (Cookiebot, Diageo/OneTrust, Oatly) et popups newsletter (Klaviyo, Shopify) couvrent les captures de Seedlip, Oatly, Mancini, To'ak, Liquid Death, Aponiente, Giacosa → prévoir un clic de fermeture dans `capture-site.mjs` avant les frames ; sinon noter la gêne en usabilité, pas en design.
- 2026-10-29 portfolio-evaluation lot 3 : Wix (Boury) renvoie une page anti-bot « Checking your request » sur le contexte mobile Playwright ; la capture mobile est inexploitable, le desktop passe.
- 2026-10-29 portfolio-evaluation lot 3 : le tool Read retire les images déjà vues du contexte (« media removed: request limit ») → rédiger l'évaluation d'un site immédiatement après avoir regardé ses captures, avant de passer au suivant.
- 2026-10-29 portfolio-evaluation lot 7 : `restaurantcastor.be` répond `ERR_HTTP2_PROTOCOL_ERROR` à Chromium (curl --http1.1 passe) → copier `capture-site.mjs` dans le scratchpad avec `args: ['--no-sandbox','--disable-http2']` ; comme ESM ignore `NODE_PATH`, importer playwright par chemin absolu (`/home/user/<dépôt>/node_modules/playwright/index.mjs`) ou lancer depuis la racine. Le site renvoie ensuite 429 si l'on réessaie trop vite : attendre une minute entre deux tentatives.
- 2026-10-29 portfolio-evaluation lot 7 : l'outil Read refuse les images au-delà d'une dizaine par réponse (« media removed: request limit ») → lire les captures par lots de 8-10 maximum, et noter un site seulement après avoir vu ses images.
- 2026-10-29 portfolio-evaluation lot 7 : un site chargé via htmx (quiquedacosta.es) détruit le contexte Playwright pendant `$$eval` (navigation) → la capture mobile manque ; protéger les `$$eval` par try/catch ou capturer le mobile avant les liens. Les descriptions de la recherche sont à vérifier : `narisawa-yoshihiro.com` est une vitrine Strikingly de 1 111 px, sans scroll horizontal ni vidéos.
